--- construir
titulo: El Complejómetro
objetivo: Construir una herramienta que estime el exponente de complejidad de cualquier operación duplicando n y midiendo.
reto:
Si un código tarda t(n) y es O(n^k), al duplicar n el tiempo se multiplica por 2^k. Así que **k = log₂(t(2n) / t(n))**. Vas a construir una herramienta que lo calcule sola.

```java
public interface Experimento<D> {
    D preparar(int n);        // crea los datos (NO se mide)
    void ejecutar(D datos);   // la operación (SÍ se mide)
}

public static <D> void analizar(String nombre, Experimento<D> e, int nInicial, int pasos)
```

Para n = nInicial, 2·nInicial, 4·nInicial… (`pasos` veces): prepara, mide `ejecutar` con calentamiento y mediana (reutiliza la lógica de `Bench`) e imprime:

```
n        tiempo (ms)   ratio   k
10000    1.204         -       -
20000    2.391         1.99    0.99
40000    4.870         2.04    1.03
≈ O(n^1.0)
```
hecho:
- Con un bucle que suma n números sale k ≈ 1.
- Con dos bucles anidados de n sale k ≈ 2.
- La estimación final usa la media de las k de los últimos pasos.
minima:
Sin la interfaz genérica: un `for` que duplica n, mide con `nanoTime` un bucle anidado e imprime el ratio.
pista1:
`k = Math.log(ratio) / Math.log(2)`. Si el ratio es ≈ 1 → O(1); ≈ 2 → O(n); ≈ 2,2 → O(n log n); ≈ 4 → O(n²); ≈ 8 → O(n³).
pista2:
Los tiempos por debajo de ~1 ms son casi puro ruido. Si te salen muy pequeños, sube `nInicial` o haz que `ejecutar` repita la operación m veces. Descarta el primer paso al calcular la estimación: casi siempre incluye calentamiento del JIT.
pista3:
```java
for (int p = 0, n = nInicial; p < pasos; p++, n *= 2) {
    D datos = e.preparar(n);
    for (int i = 0; i < 3; i++) e.ejecutar(datos); // calentamiento
    long[] t = new long[5];
    for (int i = 0; i < 5; i++) {
        D copia = e.preparar(n); // por si ejecutar modifica los datos
        long t0 = System.nanoTime();
        e.ejecutar(copia);
        t[i] = System.nanoTime() - t0;
    }
    Arrays.sort(t);
    double ms = t[2] / 1e6;
    // ratio con el paso anterior, k, imprimir...
}
```

```java
public T removeLast() {
    if (cola == null) throw new NoSuchElementException();
    T v = cola.valor;
    cola = cola.ant;
    if (cola == null) cabeza = null;  // se ha quedado vacía
    else cola.sig = null;
    tamano--;
    return v;
}
```
pista3:
El iterador es una clase interna que recuerda por dónde va:
```java
public Iterator<T> iterator() {
    return new Iterator<>() {
        Nodo<T> actual = cabeza;
        public boolean hasNext() { return actual != null; }
        public T next() {
            if (actual == null) throw new NoSuchElementException();
            T v = actual.valor;
            actual = actual.sig;
            return v;
        }
    };
}
```

objetivo: Medir cuándo gana de verdad una lista enlazada y descubrir el efecto de la caché de la CPU.

--- construir
titulo: Pila y cola circular
objetivo: Implementar una pila sobre array y una cola circular que crece sin perder el orden.
reto:
Define los contratos:

```java
public interface Pila<T> { void push(T x); T pop(); T peek(); boolean isEmpty(); int size(); }
public interface Cola<T> { void offer(T x); T poll(); T peek(); boolean isEmpty(); int size(); }
```

- `PilaArray<T>`: sobre un array que crece ×2. `pop` con la pila vacía lanza `NoSuchElementException`.
- `ColaCircular<T>`: array con `cabeza` (índice del primero) y `tamano`. Las posiciones dan la vuelta con `%`. `poll` con la cola vacía devuelve `null` (como `java.util.Queue`). Cuando se llena, crece ×2 **manteniendo el orden**.

Checks clave para la cola: llénala, saca 3, mete 3 más (el final da la vuelta al principio del array) y fuerza el crecimiento en ese estado.
hecho:
- `PilaArray` devuelve los elementos en orden inverso al de entrada.
- `ColaCircular` mantiene el orden FIFO después de dar la vuelta y de crecer.
- `poll` no mueve ningún elemento (no hay `arraycopy` en `poll`).
minima:
Solo `PilaArray` (es tu `MiLista` con restricciones: unos 10 minutos).
pista1:
Imagina el array como la esfera de un reloj: después de la última posición viene la 0. `poll` no desplaza nada: solo avanza `cabeza`. La posición donde entra el siguiente es `(cabeza + tamano) % capacidad`.
pista2:
```java
public void offer(T x) {
    if (tamano == datos.length) crecer();
    datos[(cabeza + tamano) % datos.length] = x;
    tamano++;
}
public T poll() {
    if (tamano == 0) return null;
    T x = (T) datos[cabeza];
    datos[cabeza] = null;
    cabeza = (cabeza + 1) % datos.length;
    tamano--;
    return x;
}
```
pista3:
Al crecer no basta con `Arrays.copyOf`: si la cola ha dado la vuelta, el orden en el array no es el orden de la cola. Copia elemento a elemento, `nuevo[i] = datos[(cabeza + i) % datos.length]` para i de 0 a tamano - 1, y después `cabeza = 0`.

--- medir
titulo: La cola ingenua frente a la circular
objetivo: Medir el coste de una cola que desplaza elementos frente a una circular, y comprobar por qué `Stack` es la opción equivocada.
reto:
1. **Cola ingenua:** una cola sobre `MiLista` donde `poll()` hace `remove(0)`. Con el Complejómetro: n `offer` seguidos de n `poll`, comparando la ingenua, `ColaCircular` y `ArrayDeque`.
2. **Pila:** 10 millones de `push` y `pop` alternos con `java.util.Stack`, `ArrayDeque` y tu `PilaArray`.
3. **Datamining:** abre el código fuente de `Stack` (Ctrl+clic en IntelliJ). ¿De qué clase hereda? ¿Qué palabra clave aparece en sus métodos?
hecho:
- La k de cada cola apuntada (deberías ver ≈2 frente a ≈1).
- Los tiempos de las 3 pilas.
- Sabes por qué la documentación de Java recomienda `ArrayDeque` en lugar de `Stack`.
minima:
Solo el punto 1, comparando ingenua y circular con n = 50 000.
pista1:
La ingenua es O(n) por cada `poll` (desplaza todo el array), así que n `poll` son O(n²). La circular es O(1) por operación.
pista2:
`Stack` hereda de `Vector`, una clase de Java 1.0 con todos los métodos `synchronized` (pensados para varios hilos). Aunque uses un solo hilo, pagas ese mecanismo en cada operación. Además, al heredar de `Vector` permite cosas que una pila no debería permitir, como `get(3)` o `add(0, x)`: un ejemplo clásico de herencia mal usada (semana 2).
pista3:
`ArrayDeque` es exactamente tu `ColaCircular` (un array circular), pero sirve como pila y como cola por los dos extremos. Si tus tiempos se parecen a los suyos, has construido lo mismo que la JDK.

--- aplicar
titulo: Deshacer y rehacer en el tracker
objetivo: Implementar deshacer y rehacer con dos pilas usando objetos "comando".
reto:
1. Define la interfaz:

```java
public interface Comando {
    void ejecutar();
    void deshacer();
    String descripcion();
}
```

2. Implementa `MarcarHabito` y `DesmarcarHabito`, que actúan sobre una lista de registros del tracker.
3. Crea `Historial` con dos `PilaArray<Comando>`:
   - `hacer(Comando c)`: ejecuta, mete en la pila de deshacer y **vacía** la de rehacer.
   - `deshacer()`: saca de deshacer, llama a `c.deshacer()` y mete en rehacer.
   - `rehacer()`: lo contrario.
4. Prueba esta secuencia con checks: marcar gym, marcar dientes, deshacer, deshacer, rehacer, marcar dormir, rehacer (este último no debe hacer nada).

**Misión secundaria (opcional):** `validarParentesis(String s)` con una pila: `"{[()]}"` es válido y `"{[(])}"` no. Te servirá en la semana 15.
hecho:
- La secuencia del paso 4 deja exactamente los registros esperados.
- Después de una acción nueva, rehacer no hace nada.
- Deshacer con el historial vacío no lanza excepción (devuelve false o no hace nada).
minima:
Solo deshacer (una pila) con `MarcarHabito`.
pista1:
Cada comando guarda todo lo que necesita para deshacerse: `MarcarHabito` guarda el registro que añadió, y así su `deshacer()` sabe exactamente qué quitar.
pista2:
¿Por qué hay que vaciar rehacer al hacer algo nuevo? Porque la "línea temporal" ha cambiado: lo que habías deshecho ya no encaja después de la acción nueva. Es lo mismo que pasa en cualquier editor de texto.
pista3:
Para los paréntesis: recorre el texto; si el carácter es de apertura, `push`; si es de cierre, la pila no puede estar vacía y `pop()` debe ser su pareja. Al final, la pila tiene que quedar vacía.
