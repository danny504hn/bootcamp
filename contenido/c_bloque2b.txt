--- construir
titulo: MiHashMap<K, V>
objetivo: Implementar un mapa hash genérico con encadenamiento y rehash automático.
reto:
Crea `estructuras.MiHashMap<K, V>`:

```java
private static final class Entrada<K, V> {
    final K clave; final int hash; V valor; Entrada<K, V> sig;
}
private Entrada<K, V>[] cubetas; // capacidad inicial 16 (potencia de 2)
private int tamano;
```

Métodos:

- `V put(K clave, V valor)`: si la clave existe, reemplaza el valor y devuelve el anterior; si no, añade y devuelve null.
- `V get(K clave)`, `boolean containsKey(K clave)`, `V remove(K clave)` e `int size()`.
- **Rehash:** cuando `tamano > capacidad * 0.75`, duplica las cubetas y recoloca todas las entradas.
- Clave null → `IllegalArgumentException` (simplifica las cosas).

Checks: 1 000 claves (fuerza varios rehash), reemplazar un valor, y borrar del principio, del medio y del final de una cadena.
hecho:
- Las 1 000 claves se recuperan con su valor después de varios rehash.
- Un `put` sobre una clave existente no aumenta `size()`.
- `remove` funciona aunque la entrada esté en mitad de una cadena.
minima:
`put` y `get` con 16 cubetas fijas (sin rehash ni remove).
pista1:
Es un array de mini listas enlazadas (semana 6). `get`: calcula el índice de la cubeta y recorre su cadena comparando con `equals`. Para ir más rápido, compara primero el `hash` guardado (un int) y solo si coincide llama a `equals`.
pista2:
```java
private int indice(Object clave, int capacidad) {
    int h = clave.hashCode();
    h ^= (h >>> 16);              // mezcla los bits altos con los bajos
    return h & (capacidad - 1);   // como % capacidad, pero nunca negativo
}
```
`hashCode` puede ser negativo, y `%` con negativos da un resultado negativo (índice inválido). Con capacidad potencia de 2, `& (capacidad - 1)` se queda con los bits bajos; por eso antes se mezclan con los altos.
pista3:
Crear un array genérico: `cubetas = (Entrada<K, V>[]) new Entrada[16];` (con `@SuppressWarnings("unchecked")`). Rehash: crea el array nuevo del doble de tamaño; recorre cada cubeta vieja y cada entrada de su cadena, calcula su índice nuevo y métela al principio de la cubeta nueva. Puedes reutilizar el `hash` guardado.

--- construir
titulo: La receta de dos preguntas
objetivo: Escribir 4 funciones recursivas aplicando siempre el mismo método.
reto:
Antes de cada función, escribe como comentario las respuestas a las dos preguntas:

1. **Caso base:** ¿cuál es la versión más pequeña del problema, cuya respuesta sé sin pensar?
2. **Paso:** si alguien me resolviera el problema un poco más pequeño, ¿cómo uso su respuesta?

Funciones, en orden de dificultad:

1. `int sumar(Nodo<Integer> n)`: suma una lista de nodos de forma recursiva.
2. `long potencia(long base, int exp)`: primero la versión O(n) y después la **rápida**, O(log n).
3. `int busquedaBinaria(int[] ordenado, int x, int ini, int fin)`: devuelve la posición o -1.
4. **(Jefe)** `Nodo<T> invertir(Nodo<T> n)`: invierte una lista enlazada simple de forma recursiva.
hecho:
- Cada función tiene su comentario de caso base y paso.
- `potencia(2, 62)` coincide con `1L << 62`, y la rápida hace unas 7 llamadas en vez de 62 (cuéntalas).
- La búsqueda binaria funciona con el elemento al principio, al final y ausente.
minima:
Las funciones 1 y 2 (versión O(n)).
pista1:
`sumar`: caso base, nodo null → 0. Paso: `n.valor + sumar(n.sig)`. La receta siempre tiene esta forma: un if para el caso base y un return que usa la llamada con un problema más pequeño.
pista2:
Potencia rápida, con división entera: x^n = (x^(n/2))² si n es par, y x · (x^(n/2))² si es impar. **Guarda la mitad en una variable**: `long mitad = potencia(base, exp / 2);` y después `return exp % 2 == 0 ? mitad * mitad : base * mitad * mitad;`. Si escribes `potencia(base, exp / 2) * potencia(base, exp / 2)` haces dos llamadas y vuelves a O(n).
pista3:
Búsqueda binaria: `int medio = ini + (fin - ini) / 2;`. ¿Por qué no `(ini + fin) / 2`? Porque con arrays enormes `ini + fin` puede desbordar el int y dar un negativo: fue un bug real de la JDK que pasó años sin detectarse, hasta 2006. Invertir: caso base, null o un solo nodo → devuélvelo. Paso: `Nodo<T> nuevaCabeza = invertir(n.sig); n.sig.sig = n; n.sig = null; return nuevaCabeza;`.

objetivo: Escribir un serializador JSON recursivo, el problema donde la recursión es la mejor herramienta: datos anidados de profundidad desconocida.

--- construir
titulo: MiArbol<K, V>
objetivo: Implementar un árbol binario de búsqueda genérico con operaciones recursivas.
reto:
Crea `estructuras.MiArbol<K extends Comparable<? super K>, V>` con un `Nodo` (clave, valor, izq, der):

- `put(K, V)` (si la clave existe, reemplaza el valor)
- `V get(K)` y `boolean containsKey(K)`
- `K min()` y `K max()`
- `int altura()` (árbol vacío: 0; un solo nodo: 1)
- `MiLista<K> enOrden()`: las claves ordenadas
- `MiLista<K> rango(K desde, K hasta)`: las claves del rango, **sin visitar ramas que no pueden contenerlas**

Checks: inserta 15, 10, 20, 8, 12, 17 y 25, y comprueba `enOrden`, `altura` (= 3), `min`, `max` y `rango(11, 18)`.
hecho:
- Todos los checks con el árbol de 7 nodos pasan.
- `rango` no entra en ramas imposibles (cuenta los nodos visitados).
- Insertar una clave repetida no crea un nodo nuevo.
minima:
`put`, `get` y `enOrden`.
pista1:
En cada nodo hay tres casos: la clave es menor (ve a la izquierda), mayor (ve a la derecha) o igual (reemplaza el valor). Si llegas a null, ese es el sitio del nodo nuevo.
pista2:
`enOrden`: recorre la izquierda, añade el nodo, recorre la derecha (recursivo). `altura(n)`: si n es null, 0; si no, `1 + Math.max(altura(n.izq), altura(n.der))`. `rango`: baja por la izquierda solo si `desde < n.clave`, y por la derecha solo si `hasta > n.clave`.
pista3:
El truco del `put` recursivo es devolver el nodo:
```java
private Nodo<K, V> put(Nodo<K, V> n, K k, V v) {
    if (n == null) { tamano++; return new Nodo<>(k, v); }
    int c = k.compareTo(n.clave);
    if (c < 0) n.izq = put(n.izq, k, v);
    else if (c > 0) n.der = put(n.der, k, v);
    else n.valor = v;
    return n;
}
// public void put(K k, V v) { raiz = put(raiz, k, v); }
```
